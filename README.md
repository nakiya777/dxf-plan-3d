# dxf-plan-3d

DXF の平面図を読み込み、壁（開口部・階段付き）を立ち上げ、屋根を載せて簡易な建物 3D モデルを作るブラウザアプリ。サーバーは無く、DXF はブラウザの中だけで処理する。

## 状態

- **2026-09-04:** MVP（実装計画 Task 1〜17）完了。単体テスト 193 件、E2E 8 件が通る
- 参考動画（`specs/001-dxf-massing-mvp/reference/reference.mp4`）に映るデモと機能を同一にすることがゴール。動画の流れは次の 4 段

1. DXF を読み込み、平面図の 1 階を矩形で囲むと壁・開口・階段が立ち上がる
2. 青ハンドルのドラッグで壁の高さを変える
3. 2 階も同じ手順で乗せる
4. 屋根をかけ、寄棟／切妻・向き・勾配を変える

公開先: https://github.com/nakiya777/dxf-plan-3d （公開、既定ブランチ master）

動作デモ: https://dxf-plan-3d.vercel.app/ （Vercel、本番エイリアス。誰でも開ける。デプロイ固有の `*-nakiya777s-projects.vercel.app` は Vercel Authentication で保護されているため、共有にはこの本番 URL を使う）

## 起動手順

Node 22 を前提にしている。

| コマンド | 内容 |
|---|---|

| `npm test` | 単体テスト（vitest）。193 件 |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run build` | 型検査のあと `dist/` に本番ビルドを出す |
| `npm run e2e` | E2E（Playwright、8 件）。初回だけ `npx playwright install chromium` が要る。開発サーバーは Playwright が自分で起こすので、先に `npm run dev` を打つ必要はない（動いていればそれを使う）。CI では `reuseExistingServer` を無効にしてあり、必ず自分で起こす |
| `npm run make-fixtures` | 自作フィクスチャ `fixtures/sample-house*.dxf` を `scripts/make-sample-dxf.ts` から再生成する |

## 実図面フィクスチャについて

`fixtures/forest-s/`（実在する住宅の図面）は権利上の配慮で公開リポジトリに含めず、ローカルにだけ置く。無くてもテストとビルドは通る。実図面を使う試験は **skip** として数えられ、失敗にはならない（単体 193 件中 13 件、E2E 8 件中 1 件）。判定は `src/recognize/testing.ts` の `hasForestS()`（`existsSync`）で、実図面がある環境では従来どおり全件走る。

## 使い方

1. 「DXF 平面を描く」を押して DXF ファイルを選ぶ。2D の選択ビューに図面全体が出る
   - デモなら「サンプル平面図を読み込む」でファイル選択を省ける（`fixtures/sample-house.dxf` を静的アセットとして読む）
2. 平面図の 1 階を矩形で囲む。**壁の線を跨ぐ位置で小さく囲めば、つながった図形全体に広がる**（囲みは「触れた図形を拾う種」で、全体を覆う必要は無い）。線に触れない空室の中だけを囲むと「範囲に図形がありません」と出る
3. 壁が立ち上がったら青ハンドルをドラッグする。縦方向のドラッグは高さ（0.05 m 刻み、ラベルに「壁の高さ 1.60 m」のように出る）、横方向は階の平行移動
4. 2 階は「DXF 平面を描く」からもう一度、2 階の平面図を囲む。1 階の天端にスラブ厚を足した高さに乗る。青ハンドルは最上階にだけ出る（下の階の高さは、その階が最上階のうちに決める。全階に出すと重なって掴み違えるため）
5. 「壁を透かす」を押すと、壁や板が薄く透け（不透明度 0.85）、稜線と平面図の青線が壁越しにも見える。さらにカメラに向いている外壁は 0.15 まで薄くなり、回転すると透ける壁が入れ替わる（参考動画と同じく、手前の外壁の向こうにある室内の壁やドアの弧が読める）。「壁を戻す」で通常の不透明表示に戻る
6. 「屋根をかける」を押す。橙の球（棟の両端）を棟方向にドラッグして寄棟 ⇔ 切妻、紫の回転矢印をクリックして向き（棟の方向）、緑の菱形で棟の平行移動（暫定。設計書 Q7）、右パネルのスライダーで勾配・軒の出・ケラバの出を変える

### 対応する DXF

- R12（AC1009）以降。Jw_cad の書き出し（R12・Shift_JIS）で確認済み
- 文字コードは UTF-8 / Shift_JIS を自動判別
- 単位は `$INSUNITS` を見て mm / cm / m / inch を mm に正規化。無指定なら図面の長辺が 200 未満のとき m、それ以外は mm と見なす
- ブロック（INSERT）は展開して読む
- **レイヤー名に依存しない**。壁・開口・階段は形状（平行線の帯、弧、等間隔の段）で認識する。Jw_cad のように名前に意味が無いレイヤー構成でも動く

## 既知の制約

設計書に記録済みのもの。

- forest-s の 1 階は外形が閉じず、外接矩形に落ちる。壁の隙間を埋める短い壁片（148〜252 mm）が帯として認識されないため。2 階は閉じる
- forest-s の 1 階にある弧 6 個のうち、開き戸として開口になるのは 2 個。残り 4 個は隣の壁片が 148 / 150 / 252 / 150 mm と短く帯にならず、戸を入れる隙間が無い
- 折り返し階段は直進部だけを段にする。forest-s の 1 階は直進 4 段までで、回り段と上部 2 段は 3D に出ない（等間隔 4 本以上の線の組しか段と見なさないため。3 本に下げると目地や家具も段になる）
- 緑の菱形（棟の平行移動）の機能は暫定。動画から確定できなかった（設計書 Q7）
- E2E のドラッグ試験は初期カメラと viewport 1280×800 に依存する。カメラの初期位置やパネル幅を変えたら `e2e/flow.spec.ts` の座標も直す
- 屋根は外形の外接矩形に対して生成する。L 字外形でも矩形屋根になる

## やらなかったこと

- `EdgesGeometry` の間引き・ドラッグ中の輪郭線省略。`buildBuilding` が 4〜5 ms で、必要が無かった
- `BufferGeometryUtils.mergeGeometries` による描画呼び出しの統合。同上
- コード分割（Vite の 500 kB 警告は出るが、単一画面のアプリなので分割しても初回表示は変わらない）
- L 字屋根（切り欠き・複数屋根）、下屋、階の削除、glTF 書き出し、保存・読み込み、Undo。Phase 2（設計書 §3.3）
- 依存の更新。`npm outdated` で `@types/node` 22 → 26、`vitest` 4 → 5 が出るが、どちらもメジャー更新で MVP には要らない

## テスト用フック `window.__app`

`src/ui/testHooks.ts` が `window.__app` に状態の読み書き（`getModel` / `selectRegion` / `setTopZ` など）を置く。**E2E 専用で、UI からは使わない**。青ハンドルのドラッグ量と高さの対応はカメラに依存するため、値の試験はドラッグでなくこのフックで行う。

本番ビルドにも入れている。理由は、UI から到達できる操作しか無く外部に漏れる情報も無いこと、そして `vite preview` で出したビルドに対しても同じ E2E を回せるようにするため。開発ビルドだけに限定すると本番ビルドの回帰を E2E で拾えなくなる。
