## 0. 本書の読み方

- 「**事実**」= 動画で直接観察できたこと。「**推定**」= 動画から合理的に推測したが未確認のこと。「**暫定**」= 私が置いた既定値で、マスターの一言で変えられるもの
- 各節の推定・暫定には `[推定]` `[暫定]` を付す。付いていない記述は事実か、設計上の決定である
- 未確定事項は §13 に集約した。**実装をブロックする質問は無い**。すべて暫定値で着手できる

## 1. 目的

DXF 形式の平面図を読み込み、次の操作だけで住宅規模の簡易 3D モデルを得る Web アプリを作る。

1. 平面図の範囲を囲む → 厚さ 100 mm の板（スラブ）になる
2. 板の上面をつまんで持ち上げる → 壁が、開口部（ドア・窓）と階段を伴って立ち上がる
3. 2 階の平面図で同じことをする → 1 階の上に積み上がる
4. 屋根をかける → 寄棟が載る。棟の端点・向きをつまんで切妻に変えられる。勾配・軒の出・ケラバの出はスライダー

参考動画に映るデモと**機能を同一**にすることが本書のゴールである。動画に無い機能は、プログラムとして成立させるために不可欠なもの（ファイル形式の解釈、認識失敗時の振る舞い、テスト用データ）に限って追加し、§14 に理由付きで列挙した。

用途は動画から確定できない。動画の保存先フォルダ名が「景観規制建物描画アプリ」であることから、**景観検討・ボリューム検討のための簡易建物モデル作成**が主用途と推定する `[推定]`。この推定は要件の優先度（正確な納まりより形の速さ）に影響するが、機能の有無には影響しない。

### 2.3 表示スタイル

- 背景はほぼ白、地面に 1 m 格子と細かい補助格子
- 建物は薄い灰色の面 + 濃い輪郭線（いわゆる線画風）。影は無い
- 平面図の線は各階の床面に**青**で残る。文字（部屋名）は 3D では描かれない
- 通り芯のバブル（丸 + 引出線）は各階の床面の高さに青で描かれる（25 秒の画面では 1 階・2 階の両方の高さに楕円がある）
- 屋根は濃灰、編集線（棟・隅棟）は赤
- ハンドル: 青立方体（高さ／横移動）、橙球（棟端点）、緑菱形（棟中央）、紫回転矢印（棟の向き）
- ラベル: 黒地・白文字の角丸ピル

## 3. 要件

### 3.1 確定要件（動画で観察された機能。すべて MVP）

| # | 要件 | 内容 |
|---|---|---|
| R1 | DXF 読み込み | ファイルダイアログで `.dxf` を選ぶ。Shift_JIS / UTF-8 両対応（§7.1） |
| R2 | 平面図の範囲選択 | 全画面 2D ビュー「平面図を囲んでください」。矩形ドラッグで 1 枚の平面図を選ぶ。「やめる」で戻る |
| R3 | スラブ生成 | 選択範囲の外形が厚さ 100 mm の板になる。1 階の床高さは既定 550 mm（入力可。動画は 500）。1 階の板の下には GL からの基礎を描く |
| R4 | 壁の立ち上げ | 青ハンドルを上へドラッグすると板の上面が上がり、壁が伸びる。ラベル「壁の高さ x.xx m」、0.05 m 刻み |
| R5 | 開口部の自動認識 | ドア（アーチ記号）・窓（外壁の窓記号）を認識し、壁に穴をあける。ドアは垂れ壁付き、窓は腰壁付き |
| R6 | 階段の自動認識 | 階段記号を認識し、床から階の上端まで段状の立体を作る |
| R7 | 2 階の積み上げ | 2 階分の範囲を選ぶと 1 階の上に自動で位置合わせして載る。ラベルは 1 階床からの累計高さ |
| R8 | 横移動 | 青ハンドルの水平ドラッグで階ブロックを水平移動できる（ラベル「建物の高さ / 横へ移動」） |
| R9 | 屋根をかける | 最上階の外形に寄棟を生成。勾配（寸）・軒の出・ケラバの出をスライダーで即時反映 |
| R10 | 棟の編集 | 橙: 端点を棟方向にドラッグ → 寄棟 ⇔ 切妻。紫: 棟の向きを 90° 回す。緑: 棟の平行移動 `[推定]` |
| R11 | 妻壁の自動生成 | 切妻側の外壁が屋根裏面まで伸びる |
| R12 | 3D 表示 | 軌道カメラ（回転・平行移動・ズーム）、地面格子、線画風表示、平面図線の青表示、通り芯バブル表示 |
| R13 | 長方形を描く | DXF 無しで地面に矩形を描き、板にする（ボタンの存在が事実。挙動は推定） |
| R14 | 切り欠き | ボタンの存在のみ事実。機能は未確認 → **Phase 2**（§13 Q3） |

## 4. アーキテクチャ

### 4.1 技術選定

| 層 | 選定 | 版（2026-09-03 時点の最新） | 理由 |
|---|---|---|---|
| ビルド | Vite + TypeScript | Vite 8.2.2 / TS 7.0.2（実際に入った版。設計時の想定は TS 6 だったが、着手時に 7 が最新だった） | 設定が少なく、Node 22 でそのまま動く。型で幾何計算の取り違えを防ぐ |
| UI | React | 19 | 右パネル・2D ビュー・ラベルは DOM で作るのが最短 |
| 3D | three.js | 0.185.1 | 必要なのは押し出し（`ExtrudeGeometry`）・輪郭線（`EdgesGeometry`）・軌道カメラ（`OrbitControls`）・DOM ラベル（`CSS2DRenderer`）で、すべて標準機能で足りる |
| DXF 解析 | dxf-parser | 1.1.2 | LINE / ARC / CIRCLE / LWPOLYLINE / TEXT / INSERT を JSON 化。ブロック展開は自前。**R12（AC1009）が読めることを Phase 0 で `forest-s` を使って確認する**。読めなければ、必要な 5 種のエンティティだけを読む自前パーサー（グループコードの対を舐めるだけ）に切り替える |
| 多角形演算 | polygon-clipping | 0.15.7 | 壁の帯の和集合から外形を求める |
| DXF 生成（テスト用） | @tarikjabiri/dxf | 2.8.9 | 動画相当のサンプル住宅 DXF をスクリプトで生成する（§11） |
| テスト | vitest / Playwright | 4 / 最新 | 幾何・認識は単体、操作は E2E |

依存は **exact 固定**する（幾何ライブラリの挙動が版で変わると認識結果が変わるため）。`npm install` 後は `supply-chain-check` スキルで監査する。

### 4.2 層構成

```
┌─ ui/            React。右パネル、2D 選択ビュー（SVG）、ラベル（CSS2D）
├─ viewer/        three.js シーン。カメラ、格子、ハンドル、ピッキング、ドラッグ
├─ geometry/      BuildingModel → BufferGeometry。壁（穴付き）、階段、スラブ、屋根、妻壁
├─ model/         BuildingModel と純粋関数（高さ変更、屋根パラメータ、位置合わせ）
├─ recognize/     Plan2D → PlanModel。壁・開口・階段・通り芯の認識
├─ dxf/           ArrayBuffer → Plan2D。文字コード判定、単位、ブロック展開、正規化
└─ fixtures/      実図面 forest-s/ と、scripts/make-sample-dxf.ts が生成する自作 DXF
```

- 依存方向は上から下への一方向。`model/` `recognize/` `dxf/` は three.js に依存しない純粋 TypeScript とし、vitest で網羅する
- 状態は **不変の `BuildingModel` 1 つ**。操作は `model/` の純粋関数で新しいモデルを返し、`geometry/` が全再生成する。住宅規模なら再生成は 1 フレームに収まる見込みで、N2 は §15 Phase 5 の計測で裏付ける
- Undo は MVP 外だが、不変モデルなので履歴を積むだけで後付けできる

### 4.3 座標系（不変条件）

| 空間 | 単位 | 軸 |
|---|---|---|
| DXF / Plan2D / BuildingModel | mm | X 右、Y 上（図面の北）、Z 上 |
| three.js シーン | m | X 右、Y 上、Z 手前。**変換は `(x, y, z)_model → (x, z, −y)_scene × 0.001` の 1 か所（`src/geometry/coords.ts`）だけ**。ジオメトリはモデル座標で組み立ててから最後に 1 回掛ける |

- GL（地面格子）= model Z = 0 = scene Y = 0
- 1 階の床上面 FL1 = Z = `floor1Level`。**既定 550**（動画のパネルは 500 だが、マスター指示で GL + 550 の基礎高さとする。2026-09-03 Q4 回答）
- GL から FL1 までは**基礎**として描く（§8.1）
- 「壁の高さ」ラベルは **FL1 起点の累計**（Q4 回答で確定）。2 階のラベルが 7.15 m まで上がる動画の挙動と整合する

## 5. データモデル

```typescript
/** DXF から取り出した 2D エンティティ（mm、モデル空間のみ） */
type PlanEntity =
  | { kind: 'line';   layer: string; a: Vec2; b: Vec2 }
  | { kind: 'arc';    layer: string; center: Vec2; radius: number; startDeg: number; endDeg: number }
  | { kind: 'circle'; layer: string; center: Vec2; radius: number }
  | { kind: 'text';   layer: string; at: Vec2; text: string; height: number };

/** 範囲選択で切り出した 1 枚の平面図 */
interface Plan2D { entities: PlanEntity[]; bbox: Box2; sourceName: string }

/** 認識結果 */
interface Wall     { id: string; a: Vec2; b: Vec2; thickness: number; exterior: boolean }
interface Opening  { wallId: string; offset: number; width: number; type: 'door' | 'window';
                     sill: number; head: number }              // sill/head は床からの高さ mm
interface Flight   { rect: Box2; axis: 'x' | 'y'; ascendPositive: boolean; treads: number }
interface Stair    { flights: Flight[]; landings: Box2[] }  // 直階段は flights 1 つ。折り返しは 2 つ + 踊り場
interface GridAxis { label: string; a: Vec2; b: Vec2; bubble: Vec2 }
interface PlanModel {
  walls: Wall[]; openings: Opening[]; stairs: Stair[]; axes: GridAxis[];
  outline: Polygon;            // 外壁帯の和集合の外周。閉じなければ全壁の bbox、壁 0 本なら空
  decorLines: PlanEntity[];    // 認識外の線・弧（床面に青で描く）
  warnings: string[];          // 認識失敗の注意文（§7.2 失敗時の振る舞い）。パネルに先頭 1 件だけ出す
}

/** 1 階分のブロック */
interface FloorBlock {
  id: string; level: number;   // level は 1 始まり
  plan: PlanModel;
  offset: Vec2;                // 平面図座標 → 建物座標の平行移動（位置合わせ・横移動の結果）
  baseZ: number;               // 床上面（FL）の Z
  topZ: number;                // 壁上端の Z。baseZ 以上。50 mm スナップ
}

/** 屋根。最上階の外形の外接矩形に対する棟モデル */
interface Roof {
  axis: 'x' | 'y';             // 棟の向き
  ridgeOffset: number;         // 棟の横位置。矩形中心からの距離。既定 0 [推定機能]
  inset: [number, number];     // 両端の「外壁芯から棟端点までの距離」。0 = 切妻
  pitchSun: number;            // 勾配（寸）。4.0 = 4/10
  eave: number;                // 軒の出 mm
  verge: number;               // ケラバの出 mm
  thickness: number;           // 屋根厚（鉛直）mm。既定 150 [暫定]
}

interface BuildingModel {
  floor1Level: number;         // 1 階の床高さ（GL からの基礎高さ）。既定 550
  slabThickness: number;       // 既定 100
  floors: FloorBlock[];        // level 昇順
  roof?: Roof;
}
```

## 6. 画面・操作フロー

### 7.1 `dxf/`: DXF → Plan2D

1. **文字コード**: `TextDecoder('utf-8', { fatal: true })` で読み、例外が出たら Shift_JIS で読み直す。Shift_JIS の日本語は UTF-8 として不正なバイト列になるので、この判定は確実に働く。

   **`$DWGCODEPAGE` は見ない。** v0.1.0 では「宣言があれば従う」としていたが、R2007（AC1021）以降のファイルは本文が UTF-8 でありながらヘッダに `ANSI_932` が残る組み合わせが日本語版 CAD で普通に起こり、宣言を先に信じると全レイヤー名と部屋名が文字化けする（2026-09-03 に実機で再現）。認識はレイヤー名と文字列に依存するので、例外も警告も出ないまま後続がすべて空振りする。扱う文字コードが UTF-8 と Shift_JIS の 2 種だけである以上、厳密デコードの成否が宣言より確実な判定材料になる。
2. **単位**: `$INSUNITS` があれば従う（4 = mm、5 = cm、6 = m、1 = inch）。無ければ図面範囲（`$EXTMAX` が無い・0 なら全エンティティの bbox）の長辺が 200 未満なら m、それ以外は mm と見なす `[推定]`。cm を含めるのは、住宅図面を cm で描くと範囲推定が mm と区別できず 100 倍小さくなるため
3. **対象**: R12（AC1009）以降。モデル空間のみ。OFF・フリーズのレイヤーは除外。`INSERT` はブロック定義を展開（**基点・回転・スケール**、入れ子 3 段まで）。`LWPOLYLINE` / `POLYLINE` は線分列に分解（バルジは 8 分割の弧として近似）。`DIMENSION` `HATCH` は無視。`SPLINE` は制御点を結ぶ折れ線として decorLines にだけ残す（装飾線にしか使わず、実図面に 1 件も無いため NURBS 評価器は持たない）
4. **識別子**: DXF のハンドル（5 番コード）は R12 で重複・欠落があり得るので使わず、配列の順序をそのまま識別子として扱う
5. **正規化**: 1 mm 未満の線は捨てる（実図面で 86 本が該当）。**点のマージはしない** — 全座標を丸めると精度を一律に落とすため、位置の揺れは `recognize/` の距離閾値で吸収する
6. **`Plan2D.bbox` はエンティティの外接矩形**であって `$EXTMAX`（用紙の限界）ではない。範囲選択と視点合わせが実際の描画範囲を要るため。`$EXTMAX` は単位推定にだけ使う

### 7.2 `recognize/`: Plan2D → PlanModel

Jw_cad 形式ではレイヤー名に意味が無い（§7.0）ので、**形状と文脈で判定し、レイヤーは「同じレイヤーの線は同じ種類」という手掛かりにだけ使う**。名前が当たる場合（`壁` `WALL` `建具` `階段` `通り芯` など）は判定を短絡させる。閾値の置き場は `recognize/config.ts` の 1 か所で、単体テストで固定した値だけを使う。

#### 手順

1. **帯の抽出**: 同一レイヤーで平行な線分の対のうち、距離 60–250 mm・重なり長 300 mm 以上のものが帯候補。次の 3 つを除外・分離する

   **平行の判定は向き θ を 0.5° 刻みに丸めた値の一致で行う。** 刻みの境界をまたぐ 2 本（例: 真角 0.24° と 0.26°）と、0° と 179.5° は別グループになり平行と見なされない `[暫定]`。直交図面では 0°/90° が刻みの中心なので実害は出ていない。刻み幅を変えると境界の位置が動いてどの壁が残るかが静かに変わるので、変えたら実図面で壁の本数を測り直す。

   **周期性と中央線の探索は ρ 順の窓に限る。** 群全体を走査すると密なハッチ 1 枚（4,000 本）で 1 秒近くかかり、8,000 本で N2 の 2 秒を割る（2026-09-03 実測）。窓に限れば実図面全体で 50 ms 程度。
   - **周期性**: 帯の外側に同じ間隔（±15%）で同じレイヤーの平行線が続くもの → タイル目地・ハッチ・階段踏面（サンプルで 49 m 分を正しく除外）
   - **中央線**: 帯の中央（幅の ±25%）に、帯とほぼ同じ長さ（80% 以上）の平行線があるもの → 窓・引き戸の記号として `symbolBands` に回す
   - **入れ子**: 同じレイヤーで重なる帯は外側の対にまとめる（外壁の仕上げ線 4 本 → 1 帯）
2. **壁レイヤーの決定**: 採用した帯の総延長が最大のレイヤーを壁レイヤーとする。総延長が最大の 30% 以上あるレイヤーも壁レイヤーに加える（外壁と内壁がレイヤー分けされた図面のため）`[暫定]`。サンプルでは壁 100% / 建具 23% / 設備 3% と分かれた。この閾値は図面が増えたら見直す

   **測るのは「入れ子をまとめる前」の帯である。** まとめた後で測ると比が壊れる（2026-09-03 実測）。外壁は仕上げ線 4 本 = 6 対がまとめられて 6 分の 1 に圧縮されるのに、建具の 2 本 = 1 対はほぼ圧縮されない。その結果、建具が壁の 61% になって 30% の閾値を超え、建具レイヤーが壁として扱われる。まとめ方の調整では解決しない（重なり比を 0 まで緩めても建具は 40% までしか下がらない）
3. **壁**: 壁レイヤーの帯を `Wall` にする。共線の帯は 50 mm 以内の隙間でマージ。厚さは帯の幅
4. **開口**: 共線の壁と壁の間の隙間（最大 2,500 mm）を開口候補にし、隙間内の記号で種類を決める。判定は上から順に当てる（弧があれば外壁でも開き戸）
   - 90° 前後（60–100°）の弧（半径 500–1,200 mm）があり、弧の中心（吊元）と弧の一端（閉じた戸の先端）が隙間の中で壁芯の近く（厚さ/2 + 50 mm）にあり、そのどちらかが隙間の端（戸当たり）から 100 mm 以内 → **開き戸**。開口の範囲は [吊元, 先端] を隙間に収めたもの。180° の弧は両開きで幅 = 直径

     **戸当たりの条件が要る理由（2026-09-03 実測）:** 壁の交差部では、吊元が直交する 2 本の壁の隙間の両方に入る。forest-s の洗面所の戸（半径 694）は縦壁の隙間と横壁の隙間の両方に当たり、条件が無いと 1 枚の戸が 2 つになる。戸が付いていない側では吊元も先端も隙間の途中に浮くので、この条件で分かれる
   - 中央線付きの帯（`symbolBands`）や、壁レイヤー以外の帯・線が隙間を埋めている → **外壁なら窓、内壁なら引き戸・折れ戸**（ドア扱い、sill 0）。「埋めている」= 壁と平行で、隙間の 50% 以上を覆い、隙間の端から 100 mm を超えてはみ出さない。建具レイヤーの枠の刻み（壁端に付く 20〜100 mm の線）は隙間の縁に触れるだけなので数えず、通り芯・壁芯のように壁全体を貫く線は隙間に収まらないので数えない（サンプルでは通り芯が外壁の壁芯に重なり、これが無いと隙間がすべて開口になる）
   - 記号が何も無い → **開口なしの欠き**（壁を作らない。廊下と LDK の間などの抜け）

   **実図面での結果（2026-09-03 実測、レビューで数え直し済み）:** forest-s の 1 階は弧が 6 個あるが、弧で開き戸になるのは 2 個（半径 694 の洗面所、706 の勝手口）。残り 4 個は隣の壁片が 148 / 150 / 252 / 150 mm と短く帯にならないので隙間が無い（手順 5 の実測と同じ原因）。ほかに建具レイヤーの中央線付き帯（厚さ 192）で引き戸 885 が 1 つ、非壁レイヤーの帯が隙間を埋める 885 が 1 つ取れる。窓は外壁の隙間にある 5 つ（1,670 × 2・1,035・885・1,060）が取れ、左外壁の 2 つが同じ理由で落ちる
   - **幅が `opening.minWidth`（300 mm）未満の隙間は、記号があっても開口にせず壁としてつなぐ。** 壁の T 字交差に残る 100 mm の隙間を枠の線が覆い、幅 100 mm のドアになるのを防ぐ。現実の戸は 600 mm 以上ある
   - 外壁の窓で幅 1,600 mm 以上 → 掃き出し窓（sill 0）`[暫定]`
5. **外壁の判定と外形**: 壁帯の和集合を `polygon-clipping` で取り、最大面積の外周に接する壁を外壁とする。外周を `outline` にする。**閉じなければ全壁帯の bbox にする（落とさない）**

   **「閉じたかどうか」は面積比で判定する。** 最大の環の面積が全壁矩形の外接矩形の 30% 未満なら、閉じていないと見なして bbox に落とす `[暫定]`。単純な面積の下限（1 m² など）では、閉じていない細長い環を外形として採ってしまう。

   **実図面での挙動（2026-09-03 実測）:** forest-s の 1 階は外形が閉じず、矩形に落ちる。原因は 2 か所とも図面側の事実である。(1) 左外壁の窓脇の壁片は内側の線が 252 mm / 227 mm しかなく、帯の重なり長 300 mm に届かない。(2) テラス出入口の上の壁は外側の線が枠の刻み 25〜30 mm だけで、残る内側 2 本の間隔 25 mm は厚さの下限 60 mm に届かない。最大の環は面積が bbox の 15% しかない細い帯になる。

   このとき bbox に落とすと外壁は 34 本中 13 本と正しく判定され、外壁芯の外接矩形も 9,100 × 5,915 ちょうどになる。細い環を採ると 34 本中 31 本が外壁になり、内壁がほぼ全部外壁として扱われる。**閾値を緩めても解決しない**（`minOverlap` を 250 に下げると和集合は 1 つになるが、比は 0.31 のままで外壁は 39 本中 33 本と壊れたまま）。

   **結果として、この図面の 1 階のスラブと屋根は矩形になる。** 図面のテラス側の凹みは埋まる。見た目に現れる制約だが、MVP では受け入れる。改善は Phase 2 で扱う（短い壁片の救済、枠の刻みの除去）
6. **階段**: 壁の帯にならなかった全レイヤーの線から（階段が壁と同じレイヤーにある図面もあるため）、同じレイヤー・同じ向きで長さ 600 mm 以上（階段の幅）の線が等間隔（200–350 mm、ばらつき 10% 以内）に 4 本以上並ぶ組を探し、次を満たすものを階段にする。長さの下限は、手すりの帯で 40 mm に切られた踏面線の切れ端を組にしないため（forest-s）
   - 直交する方向にも等間隔の線があって格子になっている組は除外（タイル目地）
   - 矢印線（先端に 2 本の短線）が組に重なる、または `UP` `DN` `上` `下` の文字が組の bbox から 1,000 mm 以内にある
   - 上り方向は矢印の矢先。無ければ `UP` の文字がある端。`DN` は下り（最上階の階段記号 → §8.3 の吹き抜け）
   - 折り返し階段は、向きごとの平行線の組を `flights` にし、組と組の間の空きを踊り場にする。回り段（扇形の踏面）は踊り場として平らに作る `[暫定]`
   - `ascendPositive` は**物理的に上る向き**が軸の正方向かどうか。矢印（無ければ文字）が指す向きを、`UP` ならそのまま、`DN` なら反転して求める。§8.3 が「上り順に i 段目の高さ」に使うので、吹き抜けに落ちなかった DN 階段もこれで正しい向きに建つ（レビューで意味論を統一。2026-09-03）
   - `flights` は**上り順**に並べる。先頭は、`UP` の矢印なら尾に最も近い組、`UP` 文字なら文字に最も近い組、**`DN` の矢印・文字なら尾（文字）から最も遠い組**。矢先を起点にしないのは、DN の矢印が上段の矩形の中に収まる図面では矢先も上段に最も近くなり、上段が先頭になってしまうためである。以降は直前の組の上り終端に最も近い組。矢印の軸線は踏面と平行でない線に限る（踏面の端に触れる短線 2 本で踏面自身が矢印にならないため）。組のまとめ（1,500 mm 以内）は推移的に辿る（3 組の折り返しでは 1 組目と 3 組目が離れるため）。`UP`/`DN` 文字は組の bbox に最も近いものを採る（折り返しでは両方の文字が両方の組の 1,000 mm 内に入るため）
   - **実図面での結果（修正後、2026-09-03）:** forest-s 1 階は壁 19 本（外壁 5）、ドア 4（弧 2 + 建具レイヤーの帯 2、いずれも 885 前後）、窓 5、階段 1（直進 4 段）、`decorLines` 1,690。幅の下限で T 字交差の壁片がつながり、壁は 25 本から 19 本に減った

   **実図面での結果（2026-09-03 実測）:** forest-s の 1 階は直進 4 段（踏面線 5 本、間隔 228）＋回り段＋上部 2 段の折り返し階段。回り段の扇形と上部 2 段（線 2〜3 本）は等間隔 4 本の組にならないので、`flights` は直進部の 1 本だけになり踊り場は 0 個。回り段以降は 3D に出ない。これは組の定義（4 本以上）から来る限界で、閾値を 3 本に下げると上部 2 段は取れるが、目地・家具の平行線 3 本も組になる
   - 踏面数 = 各組の線数 − 1 の合計
7. **通り芯**: 円（半径 150–400 mm）の内側に `^[XY]\d+$` か `^[A-Z]\d*$` の文字があり、円周に線分が接しているもの。**無い図面が普通にある**（サンプルには無い）ので、位置合わせ（§8.5）は通り芯に依存しない
8. **文字**: 認識には使う（`UP` `DN`）。3D には描かない（動画に無い）
9. **その他**: 上記に当たらない線・弧（寸法線・設備・家具・仕上げ目地）は `decorLines`。床面に青で描く

#### 開口の既定寸法 `[暫定]`

ドア sill 0 / head 2,000 mm。窓 sill 900 / head 2,000 mm。掃き出し窓 sill 0。`config.ts` で変えられる。

#### 失敗時の振る舞い

壁が 1 本も取れない場合だけ、板の上に線を描くにとどめ、パネルに「壁を認識できませんでした」と 1 行出す。それ以外は黙って進める（動画と同じ）。

## 8. 3D 生成（`geometry/`）

すべて `BuildingModel` からの純粋な再生成。ブーリアン演算は使わない。

### 8.1 スラブ

`outline` を `ExtrudeGeometry` で `slabThickness` 押し出し、上面を `baseZ` に合わせる。**1 階は板の下に基礎を描く**: 同じ `outline` を GL（Z = 0）から板の下面（`baseZ − slabThickness`）まで押し出し、壁と同じ材質で表示する（Q4 回答: GL から 550 の基礎高さを 3D に付加する）。`decorLines`・通り芯・通り芯のバブル（円）は、外形の内外を問わず **そのブロックの床面の高さ（baseZ + 2 mm）** に `LineSegments`（青）で描く。外形の外にある線は宙に浮いて見えるが、動画でも 2 階の高さにバブルが浮いている（§2.3）。

### 8.2 壁（開口付き）

- 壁ごとに局所座標 (s, z) を取る。s は壁芯に沿う距離、z は床からの高さ。矩形 `[0, L] × [0, H]`（H = topZ − baseZ）から、各 `Opening` の矩形 `[offset, offset + width] × [sill, min(head, H)]` を**穴**として引いた `Shape` を作る
- `head ≥ H` のときは開口が天端に達する。`Shape` の穴は閉じた輪郭でなければならないので、この開口は外周の切り欠きとして輪郭に含める。`sill ≥ H` なら開口なし。**これで動画のように、壁が低いうちは開口が上まで抜け、高くなると垂れ壁・腰壁が現れる**
- `ExtrudeGeometry` で厚さ分押し出し、壁芯を中心に置く。壁端は接続先の壁厚 / 2 だけ延長して角を閉じる（重なりは許容）
- 材質: 薄灰の `MeshLambertMaterial` + `EdgesGeometry`（しきい値 20°）の濃灰線

### 8.3 階段

全 flights の踏面数の合計を N とし、上り順に i 段目（1 始まり）を高さ `H × i / N` の直方体にする。各 flight は矩形を踏面数で等分し、上り方向は `ascendPositive`。踊り場は直前の段と同じ高さの平らな直方体。H はそのブロックの壁高さ（動画では壁と一緒に伸びる）。

**吹き抜け**: 最上階でない階の階段の矩形と、真上の階の階段の矩形が 50% 以上重なるとき、上の階の階段は段を作らず、**スラブに穴**をあける（動画 20 秒で 2 階床に階段の穴が見える根拠）。

### 8.4 屋根（棟モデル）

最上階の**外壁芯**の外接矩形を `[x0, x1] × [y0, y1]`、棟を X 方向とする（Y 方向は軸を入れ替えるだけ）。外壁芯の外接矩形は、`outline`（外壁の外面）の外接矩形を各辺でその外壁の厚さ / 2 だけ内側に寄せたもの。

- W = y1 − y0（棟に直交する幅）、L = x1 − x0（棟方向の長さ）、p = pitchSun / 10、e = eave、v = verge、He = 最上階の topZ。軒の出・ケラバの出は**壁芯から**測る（Q9 回答で確定）
- 屋根の外形（軒先線）: 棟に直交する方向は `y0 − e .. y1 + e`。棟方向は端の種別で決まる（次項）
- 棟の横位置 yr = (y0 + y1)/2 + ridgeOffset
- **棟高** Hr = He + p × max(yr − y0, y1 − yr)。ridgeOffset = 0 なら Hr = He + p × W/2
- 軒先の屋根裏面高 = He − p × e（壁芯位置で He、そこから外へ勾配なりに下がる。外壁面では He − p × 壁厚/2）
- 端 i（i = 0 が x0 側）の**種別**: `inset[i] = 0` なら切妻、それ以外は寄棟
- 端 i の外形延長: 切妻なら v、寄棟なら e
- 棟の端点 X: 切妻なら `x0 − v`（または `x1 + v`）、寄棟なら `x0 + inset[0]`（または `x1 − inset[1]`）
- **寄棟の既定 inset** = W/2（4 面の勾配が等しくなる位置）。L/2 を超えるときは L/2。v0.1.0 では W/2 + e と書いていたが、それは inset を軒先線から測った場合の値で、§5 の「外壁芯から測る」定義と食い違っていた。端面の勾配の式に代入すると p(W/2 + e)/(inset + e) = p となるのは inset = W/2 のときだけであり、隅棟もこのとき平面上で 45° になって軒先の角を正確に通る（2026-09-03 実装時に判明）
- 寄棟端の面: 三角形 `(端の軒先 2 点, 棟端点)`。**3 点を通る平面として解く**（三角形なので必ず平面になり、`ridgeOffset ≠ 0` で両軒先の高さが違っても主面と辻褄が合う。2026-09-03 レビューで「低い方の軒先に合わせる」暫定策を廃止）。`ridgeOffset = 0` のときの勾配は `(Hr − (He − p e)) / (inset + e)` で、既定位置でちょうど p になる。端点を外へ引くほど急になり、0 で鉛直（= 切妻）に至る。この連続性が「橙をドラッグすると寄棟 ⇔ 切妻」の実体である
- 主面: 台形 `(軒先 2 点, 棟端点 2 点)` × 2 面
- **屋根の高さ関数** `h(x, y) = min(主面の高さ, 寄棟端面の高さ…)`。屋根の上面である。§8.6 の妻壁で使う
- 屋根の厚み: 各面を鉛直に `thickness` 下げた面（裏面 = h − thickness）で閉じる（鼻隠しが自動で立つ）。壁の天端は上面 h まで伸ばし、屋根の厚みの中に隠す。材質は濃灰
- 編集線: 棟と隅棟を赤い `Line` で常時表示（動画どおり）

### 8.5 階の位置合わせ

2 階目以降のブロックを追加するとき、直下の階との `offset` を次の優先順で決める。

1. **通り芯ラベルの一致**: 両階に同じラベルの通り芯が X 方向・Y 方向それぞれ 1 本以上あれば、その芯が重なる平行移動を取る（動画の 1 階・2 階は X1–X3・Y1–Y3 を共有している）
2. **外壁の重ね合わせ**: 通り芯が無い図面（実図面）向け。X・Y それぞれの候補（外接矩形の中心合わせと、その軸に直交する外壁芯どうしの位置差）を作り、**候補の組 (dx, dy) を総当たりで採点する**。各組について新しい階の外壁芯を (dx, dy) だけ動かし、同じ向き・同じ位置（許容 20 mm）の壁の重なり長を合計して最大の組を採る。同点なら中心合わせに近い組。通り芯で片軸だけ決まった場合は、その軸の候補をその 1 値に固定する。

   **X・Y を独立に解いてはいけない**（2026-09-03 レビューで判明）。X の候補を採点する重なり長は Y 座標で測るが、両階の Y 系が揃っていない状態で測ると全候補が同点になり、中心合わせに退化する。2 階を 1 階から X+12,000 などに離して描いた図面は実運用で普通なので、この形は必須である。1 階と 2 階の外接矩形が同じサンプルでは、独立に解いても偶然正解になる
3. いずれもユーザーが青ハンドルの横移動で直せる

### 8.6 妻壁（屋根裏面までの壁の延長）

屋根がある間、**最上階の外壁**の天端を `z(s) = max(H, h(x(s), y(s)) − baseZ)` に置き換える。s は壁芯に沿って 100 mm 刻み、加えて屋根面の折れ目（棟・隅棟の投影）との交点でもサンプルする。内壁は `H` のまま `[暫定]`。これで切妻側の壁が三角に伸び、寄棟側は He のままになる（動画 25 秒の妻壁）。

`ridgeOffset ≠ 0` のときは軒の低い側で `h < He` になり得るが、`max` を取るので壁は削らない（屋根が壁に食い込む）。この見た目の是非は Q7 で確認する。

```
[初期: 空の地面]
   │ DXF 平面を描く                 │ 長方形を描く
   ▼                                ▼
[2D 選択] ──やめる/Esc──▶ 直前   [矩形描画] ──やめる/Esc──▶ 直前

   ▼

   ▼

```

「DXF 平面を描く」は屋根がある状態でも押せ、その場合は新しい階を最上階に積んで**屋根をその階に載せ替える** `[暫定]`。

| 外形 | 自作は矩形 7,280 × 7,280（壁芯基準では 7,280 + 壁厚）。`forest-s` は U 字で外接矩形 9,100 × 5,915 |
| 壁ジオメトリ | H = 1,000 のときドア穴が天端に抜け、H = 3,000 で垂れ壁がある（穴数で判定） |
| 屋根 | 既定で Hr = He + p W/2。inset = 0 で切妻（端面が無い、端の延長が v）。既定 inset で 4 面の勾配が等しい |
| 妻壁 | 切妻側の外壁天端が `h` と 1 mm 以内で一致。寄棟側は He |
| 吹き抜け | 2 階の階段が 1 階と重なるとスラブに穴、段は作らない |

### 11.3 E2E（Playwright）

1. フィクスチャを読み込み → 1 階を囲む → 青ハンドルを上へドラッグ → ラベルが「壁の高さ x.xx m」の書式で出て、モデルの `topZ` と一致する（`window.__app` からモデルを読む）。ドラッグ量と高さの対応はカメラに依存するので、正確な値の試験は `window.__app.setTopZ()` のようなテスト用フックで行う
2. 2 階を囲む → `offset` が通り芯一致で決まる → 7.15 m まで上げる
3. 屋根をかける → 寄棟 → 橙端点を端までドラッグ → 切妻 → 紫で向きを変える → スライダーで勾配 6.0 寸にして棟高が式どおり
4. ドラッグ中の fps を計測して 30 以上（自作・`forest-s` の 2 階建てそれぞれ）。**fps は垂直同期（60 Hz）で頭打ちするので余裕は読めない。**併せて `setTopZ` 1 回の同期コスト（ストア更新 → `buildBuilding` → ハンドル再構築。描画を含まない）を測り、20 ms 未満を固定する（2026-09-04 レビューで追加）
5. A6: 青ハンドルの横ドラッグで `offset` が変わり `topZ` が不変
6. A9: 「長方形を描く」→ 地面でドラッグ → 階が増え、以降 `setTopZ` と屋根が DXF 由来と同じに通る
7. A10: 壁レイヤーの無い最小 DXF（メモリ上で組む）を読ませても落ちず、板だけの階と壁 0 本の注意文になる

E2E は `window.__app` のテスト用フック（`src/ui/testHooks.ts`）で値を読み書きする。フックは本番ビルドにも入れる（UI から到達できる操作しか無く、preview ビルドの E2E に使うため）。範囲選択の確定処理は UI とフックで共有する（`commitRegion`）。開発サーバーは Playwright が起こし、ポートは 5173 固定（`strictPort`）
